# Bulletin brand and contact assets

These are the Al Heperek Yehuda 0.9.2 wordmark and project contact artwork for email and the daily PDF. The wordmark uses the same outlined lettering as the website, native header and launcher. The PDF embeds the JPEG bytes from `app/BibleOnSite/Resources/Images/logo_header.jpg`. The current wordmark is 1040 × 313 pixels. Email displays the same wordmark from the website's `/images/logos/header-logo.jpg`.

The four contact PNGs rasterize the website's existing SVG icons at 36 × 36, with transparent backgrounds and the original black artwork. Their shapes retain their aspect ratios inside the square canvas without redrawing or recoloring. The globe PNG uses the project-authored 24 × 24 SVG in `source/globe.svg`, rasterized with the same 36 × 36 transparent canvas. Display these icons at 16 or 18 CSS pixels.

`manifest.json` records each source path, source and output SHA-256, filename, dimensions, MIME type, size, attribution, S3 object key and public URL. The current wordmark uses the official website URL. Contact icons retain their content-addressed URLs under `https://bible-on-site-assets.s3.il-central-1.amazonaws.com/branding/daily-bulletin/`. The generator records publication targets and writes local files. Asset publication follows the existing deployment process.

## Regeneration

Run from the repository root with an existing installation of Sharp:

```sh
node web/bulletin/scripts/prepare-email-assets.mjs --sharp-module /path/to/node_modules/sharp
node web/bulletin/scripts/prepare-email-assets.mjs --check --sharp-module /path/to/node_modules/sharp
```

The script can also find the bundled Codex dependency runtime or an existing website Sharp installation. It never installs packages or contacts AWS. The renderer versions are recorded in the manifest; use those versions to reproduce the PNG bytes. `--check` compares the generated bytes and manifest without writing. Existing versioned assets are not deleted during regeneration.
